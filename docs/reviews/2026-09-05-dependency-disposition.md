# Dependency review — 2026-09-05

Release candidate: 3.2.0, working-tree source before the final release commit. This is a dependency disposition, not publication approval or hosted-CI evidence.

## Result and recommendation

The canonical pnpm audit fell from 37 findings (28 high, 9 moderate) to **6 findings (3 high, 3 moderate)**. All build-reachable advisory paths identified in this review were patched. The six retained findings have specific missing exploit preconditions described below; recommend accepting them for this release with those usage restrictions. Do not generalize that decision to other uses of these packages, or call the whole dependency tree vulnerability-free.

Registry metadata and GitHub's advisory API were refreshed on this date. `@wordpress/scripts` 34.2.0 remains the published latest release. No forced wholesale dependency upgrade was used. Compatible transitive versions were refreshed, then four parent-scoped overrides repaired upstream pins. Plugin PHP 7.0 and WordPress 5.3 floors remain unchanged. The serializer patch requires Node 20 or newer; CI uses Node 24.

## Repairs

- `adm-zip` 0.6.0 and `@wordpress/scripts` 34.2.0 were updated in the earlier maintenance step. The new audit started after those fixes.
- Compatible refresh in the canonical pnpm lock: `fast-uri` 3.1.7, `brace-expansion` 1.1.18/2.1.4/5.0.9, `postcss` 8.5.28, `ip-address` 10.7.0, `js-yaml` 3.15.2/4.3.2, `nanoid` 3.3.18, `svgo` 3.3.5, `browserslist` 4.28.8. These remove every reported finding for those package paths, including peer-induced duplicate paths through webpack, linting, Jest, and Lighthouse.
- `copy-webpack-plugin@10.2.4 > serialize-javascript` is scoped to 7.1.1. The upstream parent requests `^6.0.0`. The patched package retains its CommonJS function export and object/options API. The parent serializes transformation cache keys; this is a real build path and was patched instead of dismissed as development-only. The regression test resolves the serializer **from the parent**, verifies its version, exercises RegExp/Date injection payloads with an inert marker in an isolated VM, and checks ordinary serialization. Full webpack build and generated-code contracts pass. [Code-injection advisory](https://github.com/advisories/GHSA-5c6j-r48x-rmvq), [later serializer fix](https://github.com/advisories/GHSA-qj8w-gfj5-8c6v).
- `markdownlint-cli@0.31.1 > minimatch` is scoped to 3.1.5, replacing its `~3.0.5` pin. This stays in the CommonJS 3.x API family and closes the three reported matching-complexity findings. The otherwise unused Markdown command does not need a broader CLI major upgrade. [Advisories](https://github.com/advisories/GHSA-3ppc-4f35-3m26), [second](https://github.com/advisories/GHSA-7r86-cg39-jmmj), [third](https://github.com/advisories/GHSA-23c5-xmqv-rm74).
- `express@4 > qs` and `body-parser@1 > qs` are scoped to 6.16.0, preserving the 6.x parse/stringify API. These pins otherwise retained 6.15.3. The affected request parsers belong to the development server; patch them even though release builds do not start that server. [Advisories](https://github.com/advisories/GHSA-x5fp-wj9c-mxmx), [second](https://github.com/advisories/GHSA-4mjr-xmp4-gh2g).

Direct Playwright 1.61.1 and WordPress Scripts 34.2.0 versions are pinned so both lockfiles select the same tested direct tools. The npm lock was regenerated in an isolated directory after its incremental resolver retained a stale nested minimatch; no npm installation replaced the shared pnpm modules.

The overrides are mirrored in `package.json` for npm and `pnpm-workspace.yaml` for pnpm 11. Remove each when the named upstream parent naturally resolves a patched compatible version; run the focused dependency contract and normal build before removal. Do not widen the parent selectors silently.

## Evidence and remaining limits

Observed locally after dependency changes on Node 22.18.0 / pnpm 11.5.2:

- `pnpm run settings:check`: full webpack build plus settings/generated asset/PHP compatibility contracts passed at plugin version 3.2.0.
- `pnpm run lint:js`: passed.
- Both lockfiles resolve the same six residual advisory IDs. npm reports 29 affected packages (6 high, 23 moderate) because it also propagates findings to dependent packages; this is not 29 independent advisory IDs. `pnpm audit --prod` reports zero findings, which alone is not a build-security verdict.
- Override parity and pinned direct-version parity across both locks are checked in the dependency contract.
- `pnpm run release:check`: workflow graph, nine archive identity/failure cases, Plugin Check output handling, and the new dependency contract passed.
- CommonJS load instrumentation inherited by the build and its child processes recorded **no loads** of `markdown-it`, `linkify-it`, `extract-zip`, `@opentelemetry/core`, Lighthouse, or UUID during `settings:check`. This supports the source trace; it is not a general proof about unexecuted commands or arbitrary extension code.
- Source search found WordPress's E2E utility import only in its own Playwright global setup, which this project does not use. Source search found Markdownlint invocation only in `lint-md-docs.js`, which no package or required workflow command invokes.

Raw refreshed audit, registry versions, and advisory descriptions were retained in temporary local evidence files during the task. The final candidate still needs the owner's exact-source hosted CI, browser/Plugin Check runtime results, archive hash review, and explicit publication authorization. The alternate npm dependency tree was lock-generated and audited, not installed and built independently; release builds and runtime gates use the canonical frozen pnpm tree. Upstream ESLint peer-version warnings remain compatibility warnings; successful local lint/build is recorded, not a claim that every upstream optional command is compatible.
