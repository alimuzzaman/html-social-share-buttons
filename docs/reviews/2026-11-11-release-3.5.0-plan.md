# Release 3.5.0 plan: native sharing and PHP runtime coverage

Date: 2026-11-11.

Status: proposed implementation plan, created at the owner's request from the
[next-release research](2026-11-11-next-release-research.md). Planning baseline:
`master` / `v3.4.0`, `4742dae6de784c66ad1c768b2148b0b6e1c6a338`.
No implementation, version bump, tag, or publication has been performed.

## Outcome

Deliver one optional **Native share** action that opens the visitor's device
share menu, while retaining a useful Copy link/direct-link fallback. Strengthen
WordPress execution on PHP 8.4 and 8.5, and correct stale compatibility/release
documentation.

Use **3.5.0** as the target minor version because this adds a public feature.
Recheck the published version before changing metadata. Keep PHP 7.0 and
WordPress 5.3 as the declared minimums for this release; recommend supported
hosting versions separately.

The research supports product fit, not a measured increase in sharing. Describe
the actual capability and measured asset cost without promising more traffic.

## Scope

| Priority | Deliverable | Completion evidence |
| --- | --- | --- |
| P0 | Real WordPress execution on PHP 8.4 and 8.5 | Production candidate activates, renders, saves settings, and passes supported runtime contracts on both versions. |
| P0 | Native sharing with predictable fallback | Native success, unsupported API, cancellation, policy denial, copy failure, no-JS and custom-URL scenarios pass. |
| P0 | Backward compatibility | Existing default output, settings, hooks, shortcodes, profiles and builder content retain their behavior. |
| P1 | Targeted Pinterest image-query regression | Decoded media URL equals the original complex image URL through the final rendered anchor. |
| P1 | Current docs and release instructions | Current status is distinguishable from historical evidence; publication confirmation examples match the workflow. |
| P1 | Dependency disposition | Fresh advisory results are recorded, with fixes or justified deferrals separated from the public feature. |

Threads is the smaller alternative if native sharing is deliberately removed
from scope after the prototype. It is not an additional requirement for 3.5.0.
Mastodon, share counts, analytics, shorteners, new URL modes, parameter stripping,
custom-post-type placement controls, and new presentation controls remain later
work. Do not combine them with this release.

## Product decisions

### Action identity and defaults

- Network/action ID and CSS class: `native`.
- Domain kind: `Network::KIND_NATIVE`, distinct from ordinary share links and
  Copy link. Add `isNativeAction()`; do not overload `isCopyAction()`.
- Feature catalog ID: `native_share`; enabling setting: `icons.native`.
- Settings label: **Native share**. Enhanced frontend label: **Share…**.
- Enabled by default: **false**, including never-saved and sparse legacy
  options. Do not add a false-valued key to historical defaults if merely
  listing the key causes legacy rendering; reuse the 3.4.0 omission pattern.
- Native share has no editable remote URL template and is not a social profile
  destination. Exclude it from profile selectors, profile rendering and template
  preview/editor lists wherever Copy link already receives special handling.
- Use the shared frontend-JS badge and help text on the Settings page. Block,
  widget and builder selection controls must explain the JavaScript cost using
  their existing supported help mechanisms.
- Retain explicit network selections and ordering. Do not enable native sharing
  when existing content did not request it.

### Behavior and Copy link coexistence

Treat native sharing as an enhancement of the existing resolved context. The
server must not claim that a native share menu is available.

| Selected actions / environment | User-visible behavior |
| --- | --- |
| Native disabled | Existing output and script behavior remain unchanged. |
| Native only, JS missing | A real same-tab link to the shared page, named **Copy link**; users can copy its link address using browser controls. No clipboard promise. |
| Native only, JS running but native API unavailable or insecure context | Enhance that one fallback as Copy link using the shared clipboard behavior. |
| Native only, native API available | Replace the fallback with a real `button type="button"` named **Share…**. Preserve the raw resolved target for fallback. |
| Native + Copy, JS missing or native API unavailable | Show the explicit Copy link action once. The native slot starts as a hidden enhancement placeholder, carrying its own context, rather than a duplicate visible fallback. |
| Native + Copy, native API available | Show Share… and the explicitly selected Copy link as separate actions. |
| Native rejects with `AbortError` | Treat as cancellation or unavailable share targets; preserve the page, focus, URL and clipboard. Do not automatically copy or announce publication. |
| Other native error, Native only | Announce that sharing could not open, change the control to **Copy link**, and wait for the next user activation before copying. |
| Other native error, Native + Copy | Keep native retry available and announce that the visitor can use the existing Copy link control. Do not inject another Copy link control. |

The hidden placeholder is only for the new native action and must not remove or
rewrite an explicitly selected Copy link. Scope coexistence to the same rendered
group; never merge unrelated groups based on `document.title` or page location.

Use a generic local share icon in every supported icon set/shape. Enhanced
buttons need focused CSS coverage because the existing icon-pack selectors
primarily target anchors. Extend selectors narrowly to native buttons without
changing existing link dimensions or introducing a theme-wide button reset.

### Shared URL, title and browser behavior

- Use the existing server-resolved URL, after applicable legacy/final URL hooks,
  and the corresponding `ShareContext` title. Do not scrape the document-wide
  canonical tag or use `document.title` for loop-item controls.
- Pass the resolved URL as a raw URL, not as a percent-encoded query component.
  Native sharing has no external endpoint to construct.
- Preserve explicit custom URLs, post IDs, archive-loop contexts, existing
  browser-URL eligibility and final-hook suppression rules.
- When browser-URL enhancement is eligible, use the same validated raw slot and
  click-time URL calculation as Copy link. Read it synchronously within the
  native click handler; correctness must not depend on script/listener order.
- Keep fallback targets synchronized too, including hidden native placeholders
  and controls that have already been enhanced. Preserve query strings,
  fragments, ports, encoded paths and repeated query parameters.
- Validate native payloads as HTTP(S) page URLs. Unsupported/invalid payloads
  must not reach `navigator.share()` or trigger silent navigation. Retain the
  server's escaped fallback behavior and offer a clear failure message.
- Native payload is `{title, url}`. Do not include descriptions, files, images,
  analytics metadata or an extra copy of the URL inside `text` in this release.

### Browser runtime contract

Feature-detect `navigator.share` in a secure context; use `navigator.canShare`
when available without requiring it on browsers that implement `share` alone.
Catch both synchronous exceptions and promise rejections. Exposed methods are
not proof that the current policy or platform permits sharing.

Call `navigator.share()` directly during user activation. No awaited operation,
clipboard write, popup or network fetch may precede it. Permit one outstanding
native call per document; guard repeated clicks across all groups and restore
control availability when the operation settles.

Support native button Enter/Space activation, focus preservation, translated
polite status messages and idempotent initialization for dynamically added
groups. Keep actual navigation anchors available if enhancement cannot run.
Do not announce **Shared successfully**: API resolution does not prove that a
destination published the content.

## Implementation map

Changes below are planned; existing paths were checked while preparing this
document. New module names are proposed implementation locations.

| Area | Files / required changes |
| --- | --- |
| Domain and network registration | `src/Domain/Network/Network.php`, `src/Infrastructure/Definition/BuiltInNetworkProvider.php`: register the new action kind, default-off identity and raw-page target. |
| Resolution and context | `src/Application/Rendering/ResolveShareUrl.php`, `BuildShareButtons.php`, `src/Infrastructure/WordPress/Rendering/HookedShareUrlResolver.php`: route the native action through existing hooks and raw URL descriptors; filter action-only entries from profile links. |
| Render data | `src/Domain/Rendering/ResolvedButton.php`: carry the context title and action data with backward-compatible optional constructor arguments, or an equivalently compatible internal data object. Preserve existing callers and descriptor validation. |
| Markup | `src/Presentation/Frontend/HtmlRenderer.php`: emit native fallback/placeholder, escaped context/labels, raw descriptor and error messages; preserve ordinary anchor markup. |
| Feature discovery and assets | `src/Domain/Frontend/FrontendFeatureRegistry.php`, `src/Presentation/Rendering/RenderFacade.php`, `src/Presentation/Frontend/AssetCollector.php`, `src/Bootstrap/PluginConfig.php`, `PluginFactory.php`: collect `native_share` and enqueue `hssb-native-share` once only when requested. |
| Native runtime | New `src/js/native-share.js`: progressive enhancement, payload selection, one pending operation, cancellation/error handling and dynamic groups. |
| Shared JS helpers | Extract reusable clipboard behavior from `src/js/copy-link.js` into a small shared module; extract only the raw descriptor/URL calculation needed from `src/js/browser-url.js`. Preserve current Copy link behavior and tests; avoid a second URL-rule implementation. |
| Settings and selection surfaces | Settings defaults/owned keys/codecs, `src/Presentation/Admin/SettingsPayloadBuilder.php`, `src/js/admin/settings/settings-renderer.js`, `src/js/blocks/shared/networks.js`, block inspectors and integration controls: add explicit opt-in selection, help and action-only filtering. Inspect all hard-coded network lists, including generated code and legacy APIs. |
| Icons and appearance | `resources/iconsets/`, existing icon generators, legacy network assets, `assets/frontend/button-appearance.css`: add all supported icon shapes and isolated native-button treatment. |
| Build and translation | `package.json`, generated `build/` assets, localization catalogs and build-boundary/archive checks: include the native entry point, translated fallback/status text and no unexpected frontend dependencies. |

Native-only pages may reuse clipboard helper code inside the native bundle; they
must not enqueue the standalone Copy link bundle solely to implement fallback.
Pages explicitly rendering Copy link may load both feature bundles once each.
Inspect the built files for unintended shared chunks or WordPress/jQuery runtime
dependencies before accepting the asset contract.

## Compatibility work

### Required matrix

Retain the existing lanes and add the following. Resolve the current stable
WordPress version at implementation time and record actual versions in results.

| Lane | Coverage |
| --- | --- |
| PHP 7.0 / WP 5.3 | Existing exact-ZIP activation and functional surface smoke; retained runtime floor. |
| PHP 7.4, 8.0, 8.2, 8.3, 8.4, 8.5 | Production Composer install and distributed-file syntax. Add missing 8.2/8.4 lanes. |
| Current stable WP / PHP 8.4 | Exact-ZIP activation/surface assertions plus regular, AJAX and multisite contracts using a compatible test harness. |
| Current stable WP / PHP 8.5 | Same runtime coverage; identify tool/core diagnostics separately from plugin failures. |
| Existing WP 6.8, fixed WP 7.1 and latest / PHP 8.3 | Preserve their current coverage and distinguish smoke-only rows from full PHPUnit rows. |
| PHP 8.6 prerelease / WP prerelease | Optional non-blocking canary; never counted as evidence for a stable compatibility claim. |

Turn on `E_ALL` for relevant runtime probes. Capture plugin-owned warnings and
deprecations, including ones reported with a vendor/core call site: inspect the
trace or isolated triggering operation rather than classifying only by filename.
Do not globally suppress deprecations to make PHP 8.5 green. Any allowance for
external diagnostics must be narrow, documented and reviewed.

If modern test tools cannot run a lane, keep its activation/surface smoke
required and record the missing full-suite coverage explicitly. Resolve the
tooling issue before describing that lane as full PHPUnit acceptance.

Preserve production PHP 7.0 syntax and separate `require-dev` constraints from
the shipped runtime. Do not introduce nullable type syntax, typed properties or
other newer syntax while keeping a 7.0 declaration.

### Targeted regressions

- Pinterest: an image URL containing a query, ampersands, Unicode/encoded path
  segments and spaces must survive final HTML escaping and one query decode
  unchanged. Exercise resolver and final-anchor output.
- Settings: native off for fresh/missing/sparse/malformed settings; enable/save/
  reload/disable works; extension-owned data, retired fields and custom existing
  templates survive both AJAX and Settings API save paths.
- Legacy/default output: existing golden fixtures remain unchanged when native
  is not requested; do not refresh old baselines merely to hide a regression.
- Browser URL: native action respects final URL hooks, explicit custom targets,
  loop posts, unsupported descriptors and click-time history/hash changes.

## Execution order and reviewable changes

1. **Compatibility and documentation.** Add the PHP lanes and runtime reporting;
   record fresh results and any actual defects. Correct current-status docs and
   the publication-confirmation example. Keep behavioral fixes separate if any
   new lane exposes a defect.
2. **Native-sharing prototype.** Implement one default-off action through the
   canonical pipeline, initially using one icon set. Prove native-only and
   native+copy behavior, synchronous URL selection and keyboard semantics before
   expanding the UI. Do not ship the incomplete prototype.
3. **Complete integration.** Finish all icon sets, selection surfaces,
   help/JS notices, translations, build entries, profile/template exclusions and
   action collection. Exercise every maintained renderer.
4. **Acceptance and maintenance.** Run the tests below; record asset bytes and
   request captures. Run a fresh dependency advisory review. Handle necessary
   dependency fixes in their own changes; defer unrelated major upgrades unless
   they are required to pass supported tests or resolve a reviewed advisory.
5. **Release preparation.** Bump aligned metadata only after behavior is accepted;
   update docs/screenshots as needed, build the exact production candidate and
   record its hash and evidence. Runtime implementation and publication remain
   distinct steps.

Each stage has a concrete exit gate. If the prototype cannot preserve URL
contracts or accessible fallback behavior, remove it from the candidate rather
than weakening those gates. A maintenance-only candidate can be considered if
the compatibility work finds a user-visible fix; choose its version from the
actual final scope.

## Verification and acceptance

Add focused tests using existing suites where practical:

- Domain, defaults, URL/descriptor, profile exclusion, renderer parity and asset
  collection contracts for the new action.
- New `tests/native-share-smoke.js`, wired into `settings:check` and CI: supported
  API, absent API, absent `canShare`, insecure context, invalid payload,
  synchronous throw, policy rejection, `AbortError`, success, pending/repeated
  clicks, independent groups, dynamic content and no duplicate fallback.
- Preserve current Copy link/browser-URL smoke behavior after helper extraction.
- Browser tests for native-only/native+copy across inline/floating placements,
  all icon sets/shapes, all appearances, keyboard/focus and no-JS behavior.
- Gutenberg selection/save/reload and forced-iframe preview; widget, shortcodes,
  direct PHP, Elementor, and supported WPBakery storage/render contracts.

Also run the exact candidate Plugin Check and browser workflow. Preserve the
documented licensed-WPBakery editor-picker skip; do not count it as an editor
pass. The existing source-only checks from the research session are a baseline,
not acceptance evidence for new code.

Mocked browser APIs verify the plugin's logic but cannot prove OS integration.
Record real-device native-sheet opening, cancellation and application handoff
on iOS Safari and Android Chrome. Check desktop Chrome/Edge and Safari behavior
and Firefox fallback. If device access is unavailable, record that remaining
acceptance gap before release review instead of substituting a mock result.

Performance/privacy gates:

- Default configuration: no new markup or plugin frontend JavaScript.
- Enabled native action: one local native runtime per page, with dependencies
  limited to bundled local helpers; no remote SDK, analytics or count request.
- No separate Copy link script solely for native-only fallback.
- Record compressed/uncompressed bundle bytes and actual frontend requests
  against the 3.4.0 baseline; investigate unexpected runtime dependencies,
  blocking requests or layout shifts.
- No new database table, migration write, external service credential or
  telemetry collection.
